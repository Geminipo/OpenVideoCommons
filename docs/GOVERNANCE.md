# Governance

OpenVideoCommons needs governance before it needs scale. The project should be open enough to invite global participation and strict enough to protect trust.

## Current Governance Status

The project is in founder-led bootstrap mode.

Bootstrap founder:

- [Geminipo](https://github.com/Geminipo)

During bootstrap, maintainers should optimize for:

- Clear technical scope.
- Legal and safety caution.
- Verifiable contribution records.
- Transparent decisions in GitHub issues and pull requests.

## Maintainer Responsibilities

Maintainers are responsible for:

- Reviewing benchmark result submissions.
- Protecting schema compatibility.
- Rejecting unverifiable or unsafe data.
- Publishing public reports with clear methodology.
- Labeling issues for new contributors.
- Documenting major project decisions.

## Contribution Recognition

Recognition should be public, non-speculative, and tied to accepted contributions.

Appropriate recognition:

- Contributor lists.
- Report acknowledgements.
- GitHub history.
- Public contribution records.
- Research or technical report co-authorship where appropriate.

Inappropriate recognition:

- Token promises.
- Guaranteed financial returns.
- Unverified compute claims.
- Pay-to-rank mechanics.

## Decision Process

Early decisions can be made by maintainers after public discussion. As the project grows, governance should evolve toward working groups:

- Benchmark working group.
- Data governance working group.
- Model recipes working group.
- Safety and abuse review group.
- Infrastructure working group.

Major changes should be proposed through request-for-comment documents under `docs/rfcs/`.

## Safety and Legal Boundaries

The project should reject:

- Private or sensitive videos.
- Copyright-unclear training data.
- Deepfake abuse workflows.
- Non-consensual likeness use.
- Benchmark records that hide model, prompt, or hardware details.
- Claims that cannot be reproduced or audited.
